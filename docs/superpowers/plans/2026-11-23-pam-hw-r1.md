# pam-hw R1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A per-user USB-presence PAM module (pam_hw.so) — stick enrolled ⇒ passwordless login (sufficient) or required presence (mandatory); plus the `pamhw-probe` helper for discovery and self-service enrollment.

**Architecture:** Pure, unit-tested core (config parser, identities parser, sysfs USB scanner, evaluator, identities CRUD) consumed by two thin frontends: the PAM module and the probe CLI. Testability comes from `sys_root`/path overrides instead of mocks.

**Tech Stack:** C99, gcc (`-fPIC -shared` for the module, plain binary for the probe), PAM API, syslog(3)/pam_syslog, plain-assert test harness. No OpenSSL in R1 (no crypto until R3). No `system()` anywhere.

**Spec:** `docs/superpowers/specs/2026-11-23-pam-hw-design.md` (R1 section + behavior matrix + enrollment rules)

## Global Constraints

- Paths verbatim: `/etc/pamhw/identities`, `/etc/pamhw/pamhw.conf`, secrets later under `/etc/pamhw/secrets/`; dir mode 0700, identities 0644, secrets 0600 (R3).
- Module file: `pam_hw.so`; helper binary: `pamhw-probe`.
- USB identifier format everywhere: `vid:pid[:serial]`, hex lowercase, colon-separated.
- No `system()`, no shell-outs, no new external dependencies in R1.
- Failure matrix verbatim from spec: absent ⇒ `PAM_IGNORE`/`PAM_AUTH_ERR`; present+pass ⇒ `PAM_SUCCESS`; present+fail ⇒ `PAM_AUTH_ERR` both modes; internal error ⇒ `PAM_IGNORE`/`PAM_AUTH_ERR`; remote ⇒ `PAM_IGNORE` always.
- Aggregation: best result wins — any passing device ⇒ success; else any deny ⇒ deny; else ignore.
- Unenrolled device (unclaimed or claimed by another user) ⇒ treated as absent.
- `make install` never edits `/etc/pam.d/*`.
- Non-root probe writes: invoking user from `SUDO_UID` (fallback real uid), own-username lines only, presence tier only, hijack guard on identifiers owned by others; root manages all.
- Garbage serial (empty, all-zero, non-printable) ⇒ treated as no serial ⇒ identifier is `vid:pid` only.
- Missing `/etc/pamhw/pamhw.conf` ⇒ built-in defaults (sufficient/presence/3000ms/debug off/sys_root=/sys); missing identities file ⇒ zero devices. Neither is an error.

## Review Focus

1. **Root hubs / host controllers** (`usb1`…`usbN`) expose `serial` and must never appear in scans or match identities — most dangerous false-positive. Test in Task 4.
2. **Garbage serials** (seen on real hardware: all-zero MediaTek) must collapse to `vid:pid` matching, never to a literal `"000000000"` identifier. Test in Task 4.
3. **Malformed identities line sandwiched between valid ones** ⇒ valid lines still parse and match, warning logged. Test in Task 2.
4. **Remote-session markers** (`PAM_RHOST` non-local, `PAM_TTY`=`ssh`/`notty`) ⇒ `PAM_IGNORE` even in mandatory mode with the device present. Test in Task 5.
5. **Fresh install with no `/etc/pamhw/` at all** ⇒ defaults, zero devices, sufficient ⇒ `PAM_IGNORE`, no crash, no error log spam. Test in Task 5.
